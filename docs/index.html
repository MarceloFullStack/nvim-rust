Manual do Neovim Rust

Sua config, explicada de baixo pra cima — da gramática do Vim até expandir uma macro do serde e mandar o erro pro Claude sem sair do editor.

nvim 0.12.5 startup 38 ms 38 plugins 25 parsers treesitter tema Tokyo Night leader = espaço
Quer essa config na sua máquina? 
git clone https://github.com/MarceloFullStack/nvim-rust.git
cd nvim-rust && ./install.sh
Ver no GitHub Baixar .zip O que vem dentro

O instalador resolve dependências do sistema, toolchain Rust via rustup, Nerd Font, plugins, parsers do treesitter e ferramentas do Mason. Configs existentes viram .bak — nada é apagado. Rode com --dry-run pra ver o que faria antes. Arch, Debian/Ubuntu, Fedora, openSUSE e macOS.

Setup

O que foi instalado

Nenhum "distro" pronta (LazyVim, NvChad). Essa config é sua, cada linha é legível e você pode mudar qualquer coisa sem lutar contra abstrações de terceiros.

Estrutura dos arquivos

~/.config/nvim/
├─ init.lua              ← ponto de entrada; define o leader e chama o resto
└─ lua/
   ├─ config/
   │  ├─ options.lua     ← opções do editor (número de linha, indentação...)
   │  ├─ lazy.lua        ← bootstrap do gerenciador de plugins

   │  └─ autocmds.lua    ← comportamentos automáticos

      ├─ editor.lua      ← movimento, git, busca, sessões

      ├─ rust.lua        ← rustaceanvim + crates.nvim
      ├─ ai.lua          ← Supermaven + Sidekick
      └─ dap.lua         ← debugger

Setup

Primeiro boot

Antes de tudo

Configure a fonte do seu terminal para Hack Nerd Font (já instalada no sistema). Sem ela, todos os ícones viram quadradinhos. No Kitty: font_family Hack Nerd Font Mono. No Alacritty: family: Hack Nerd Font Mono. No GNOME Terminal / Konsole, é no menu de preferências do perfil.

Checagem de saúde

Abra o Neovim e rode:

:checkhealth

Vale olhar especificamente:

  • :checkhealth lazy — plugins
  • :checkhealth nvim-treesitter — parsers
  • :checkhealth mason — ferramentas externas
  • :checkhealth sidekick — quais CLIs de IA ele encontrou
  • :LspInfo — dentro de um .rs, mostra se o rust-analyzer anexou
Primeira vez num projeto Rust

O rust-analyzer precisa indexar tudo antes de ficar útil. Num projeto médio leva 10–60 s; num workspace grande, mais. O fidget mostra o progresso no canto inferior direito. Enquanto ele indexa, o autocomplete vem incompleto — é normal, não é bug.

As três teclas que resolvem qualquer dúvida

EspaçoSegure e espere. O which-key abre um menu com tudo que existe a partir dali. Navegue pelos submenus. Esse é o caminho para aprender a config sem decorar nada.
EspaçoskBusca fuzzy em todos os atalhos ativos, com descrição. Digite "rust", "git", "debug".
:help assuntoA documentação do Vim é excelente e offline. :help text-objects, :help registers.

Trilha · 01

A gramática do Vim

Isso aqui é o conceito que separa quem "usa o vim" de quem é fluente. Não são atalhos decorados — é uma linguagem com verbos, objetos e advérbios que se combinam.

Toda edição segue a forma:

[quantas vezes] verbo [quantas vezes] objeto

Verbos (operadores)

ddelete — apaga
cchange — apaga e entra em modo de inserção
yyank — copia
vvisual — seleciona
> <indenta / desindenta
gccomenta / descomenta
=reindenta
gsaenvolve com aspas/parênteses (do mini.surround)

Objetos (movimentos e textobjects)

w b epalavra pra frente / pra trás / fim da palavra
$ 0 ^fim da linha / começo absoluto / primeiro caractere não-branco
} {próximo / anterior parágrafo (bloco separado por linha em branco)
i(inner parênteses — o conteúdo dentro
a(around parênteses — conteúdo e os parênteses
ifo corpo da função (via treesitter)

Agora combine

dwapaga uma palavra
3dwapaga três palavras
ci(troca tudo dentro dos parênteses — o clássico para reescrever os argumentos de uma chamada
yifcopia o corpo da função inteira
da"apaga a string com as aspas
>i{indenta o bloco inteiro
gcifcomenta a função toda
O insight

Você nunca decora ciw, ci(, ci", cif como quatro comandos. Você aprende um verbo (c) e quatro objetos, e a combinação sai sozinha. Aprender 8 verbos e 15 objetos te dá 120 comandos que você nunca precisou memorizar.

Atalhos que dobram o verbo

Repetir o verbo aplica ele na linha inteira: dd apaga a linha, yy copia a linha, gcc comenta a linha.

Trilha · 02

Os modos

O canto inferior esquerdo (na lualine) sempre mostra em que modo você está, com cor própria. Quando estiver perdido, Esc duas vezes volta pro normal.

NORMAL
O estado de repouso. Aqui as letras são comandos, não texto. É onde você passa a maior parte do tempo.
Esc volta pra cá
INSERT
Digitação normal, como em qualquer editor. Entre com i, a, o, c.
jk sai (mapeado na sua config)
VISUAL
Seleção. v por caractere, V por linha, Ctrl+v em bloco (colunas!).
Depois de selecionar, aplique um verbo
COMMAND
Entre com :. Aqui moram :w, :q, :%s/a/b/g e todos os comandos de plugin.
Na sua config abre flutuante no centro
TERMINAL
Dentro de um terminal embutido. Aqui as teclas vão pro shell, não pro Vim.
EscEsc volta pro normal
OPERATOR-PENDING
O instante entre você apertar d e escolher o objeto. Você não "vê" esse modo, mas é ele que dá sentido à gramática.
Dura milissegundos

As formas de entrar em INSERT

Escolher a certa economiza um movimento inteiro:

iinsere antes do cursor
ainsere depois do cursor (append)
Iinsere no primeiro caractere não-branco da linha
Ainsere no fim da linha — o mais usado de todos (pra adicionar ;, ?, .await)
oabre uma linha nova abaixo e insere
Oabre uma linha nova acima e insere
givolta pro último ponto onde você estava inserindo

Trilha · 03

Movimento

Regra de ouro: nunca segure j apertado. Se você está repetindo uma tecla, existe um movimento melhor.

Dentro da linha

fxpula pro próximo x na linha (find). ; repete, , repete pra trás.
txpula pra logo antes do próximo x (till). Combina com verbos: dt, apaga até a vírgula.
Fx Txas mesmas, pra trás
w bpalavra pra frente / pra trás (para em pontuação)
W Bo mesmo, mas só quebra em espaço — útil pra pular foo::bar::Baz inteiro
%pula pro par correspondente do (, [, { sob o cursor

Na tela

s + 2 letrasFlash. Digite duas letras de qualquer lugar visível e labels aparecem sobre cada ocorrência. Aperte o label e você está lá. É o movimento que você mais vai usar.
SFlash no treesitter: labels sobre os nós da árvore, pra selecionar expressões/blocos inteiros
H M Ltopo / meio / base da tela (High, Middle, Low)
zzcentraliza a tela no cursor. zt joga pro topo, zb pra base.
Ctrl+d / Ctrl+umeia página abaixo / acima — já centralizado na sua config

No arquivo

gg / Gtopo / fim do arquivo
42Gvai pra linha 42. (Ou :42.)
5j5 linhas abaixo. Com relativenumber ligado, o número está escrito na tela — é só ler e digitar.
Ctrl+oVolta pro lugar anterior da jumplist. Pulou pra uma definição e quer voltar? É esse.
Ctrl+iavança na jumplist (o "forward" do navegador)
``alterna entre a posição atual e a última
]f / [fpróxima / anterior função (treesitter)
]c / [cpróximo / anterior struct ou impl
]d / [dpróximo / anterior diagnostic (erro ou warning)
]e / [esó erros, ignorando warnings
]h / [hpróximo / anterior hunk do git
]t / [tpróximo / anterior TODO
O padrão dos colchetes

] é sempre "próximo", [ é sempre "anterior". Uma vez que você internaliza isso, cada novo plugin que adiciona um ]algo já nasce aprendido.

Trilha · 04

Edição

O ponto

A tecla mais subestimada do Vim

. repete a última alteração. Mudou uma palavra com ciwnovoEsc? Vá até a próxima ocorrência e aperte .. Combine com n (próxima busca) e você tem um "substituir com confirmação" mais rápido que qualquer regex: n.n.n.

Desfazer

u / Ctrl+rdesfaz / refaz
EspaçosuÁrvore de undo. O Vim guarda uma árvore, não uma pilha — nada que você escreveu se perde. Navegue visualmente por todos os estados anteriores do arquivo.
O undo é persistente: feche o nvim, reabra amanhã, e o u ainda funciona.

Manipular linhas

Alt+j / Alt+kmove a linha (ou a seleção) pra baixo/cima. Reindenta sozinho.
yypduplica a linha
Jjunta a linha de baixo com a atual
x / rcapaga o caractere / substitui por c
~alterna maiúscula/minúscula do caractere
gUiw / guiwpalavra pra MAIÚSCULA / minúscula
Ctrl+a / Ctrl+xincrementa / decrementa o número sob o cursor

Colar sem perder o que você copiou

Problema clássico: você copia algo, seleciona um trecho, cola por cima — e agora o registrador tem o texto substituído, não o seu. Solução na sua config:

Espaçop (em visual)cola por cima mantendo o registrador intacto. Pode colar a mesma coisa em 10 lugares.
EspaçoD (em visual)apaga sem sujar o registrador

Seleção em bloco (colunas)

O truque que parece mágica pra quem vem de IDE:

  1. Ctrl+v entra em visual-block
  2. jjj desce, selecionando uma coluna estreita
  3. I (maiúsculo) insere no começo, ou A no fim
  4. Digite o texto e aperte Esc — ele aparece em todas as linhas

Uso real em Rust: adicionar pub em 12 campos de uma struct, ou #[serde(skip)] numa coluna.

Substituir

:%s/velho/novo/gsubstitui no arquivo inteiro. Sua config mostra preview ao vivo enquanto você digita (inccommand).
:%s/velho/novo/gco c pede confirmação a cada ocorrência
:'<,'>s/a/b/gsó na seleção visual (aparece sozinho se você apertar : em visual)
Espaçosrgrug-far: busca e substituição no arquivo, com painel e preview
EspaçosRo mesmo, no projeto inteiro — o substituto do "Replace in Files"
Em Rust, prefira o LSP

Pra renomear um símbolo, Espaçocr (rename do LSP) é sempre melhor que regex: ele entende escopo, renomeia em todos os arquivos e não toca em strings ou comentários que por acaso têm o mesmo texto.

Trilha · 05

Textobjects

Onde a coisa fica séria. Textobjects entendem a estrutura do código, não posições de cursor.

Todos seguem o padrão verbo + i/a + objeto, onde i = inner (só o conteúdo) e a = around (com os delimitadores).

Sintáticos
iw / awpalavra / palavra com o espaço
i( i[ i{dentro dos delimitadores
i" i' i`dentro das aspas
ipo parágrafo / bloco
itdentro de uma tag (HTML/XML)
Semânticos — via treesitter
if / affunção — corpo / função inteira com assinatura
ic / acclasse — em Rust: struct, enum, impl, trait
ia / aaargumento — daa remove o parâmetro e a vírgula
iobloco — o corpo de um if, match, loop, for
ihhunk do git — dih reverte a alteração local

Combos que valem ouro em Rust

cifreescreve o corpo da função sem tocar na assinatura
dafdeleta a função inteira, docs e atributos inclusos
vicseleciona o impl inteiro (pra mandar pra IA, por exemplo)
yaacopia um argumento com a vírgula, pronto pra colar em outra assinatura
cioreescreve o braço de um match

Trocar argumentos de lugar

Espaçocnatroca o argumento sob o cursor com o próximo
Espaçocpatroca com o anterior

Surround

gsa + objeto + delimitadorenvolve. gsaiw" põe aspas na palavra.
gsd + delimitadorremove. gsd" tira as aspas.
gsr + velho + novotroca. gsr'" converte aspas simples em duplas.

Trilha · 07

LSP — inteligência de código

Vale pra qualquer linguagem com servidor configurado. Em Rust, quem fornece é o rust-analyzer.

Navegar pelo código

gdIr pra definição. Funciona até dentro das dependências e da std.
grtodas as referências — quem chama isso
gIimplementações (quem implementa este trait)
gydefinição do tipo (não da variável — do tipo dela)
Ctrl+ovolta de onde veio
Espaçocssímbolos do arquivo — pule direto pra qualquer fn, struct, impl
EspaçocSsímbolos do projeto inteiro

Entender

KHover: tipo, assinatura e doc do item sob o cursor. Em Rust vem com ações — aperte K de novo pra entrar na janela e navegar pelos tipos mencionados.
Espaçocdabre o erro da linha por inteiro (útil quando o virtual text corta)
Espaçouhliga/desliga os inlay hints — os tipos inferidos que aparecem em cinza
Inlay hints em Rust

Vêm ligados por padrão, e são o maior ganho de produtividade da config. Você escreve let x = foo(); e o editor mostra let x: Result<Vec<String>, Error> = foo(); sem você pedir. Você para de precisar abrir a doc pra saber o que uma função devolve. Se a tela ficar poluída, Espaçouh desliga.

Mudar

EspaçocrRenomear símbolo em todo o projeto, com consciência de escopo
EspaçocaCode action. O menu de "conserta pra mim": importar o que falta, preencher os braços de um match, envolver em Ok(), derivar traits, extrair pra função.
Espaçocfformatar agora (já roda sozinho ao salvar)
Espaçoclroda o code lens sob o cursor (ex.: o "Run test" acima de um #[test])
O reflexo a treinar

Viu um sublinhado vermelho? Espaçoca antes de qualquer outra coisa. O rust-analyzer resolve a maioria dos erros sozinho — principalmente imports faltando e match não-exaustivo.

Trilha · 08

Rust no dia a dia

Tudo sob Espaçor. Só funciona em buffers .rs.

Rodar e testar sem sair do editor

EspaçorrRunnables. Lista tudo que dá pra executar a partir de onde o cursor está: o binário, o teste sob o cursor, o módulo de testes, um benchmark. Escolha e ele roda num terminal.
EspaçorRrepete o último runnable sem perguntar nada — o loop de TDD
Espaçortsó os testes
Espaçorddebuggables — como o runnables, mas anexa o debugger
EspaçorLrepete o último debuggable
O ciclo que vale treinar

Escreva o teste → Espaçorr e escolha ele uma vez → daí em diante só EspaçorR depois de cada alteração. Você nunca mais alterna pro terminal pra rodar cargo test.

Entender o que o compilador está fazendo

EspaçoreExpandir macro. Põe o cursor num #[derive(Serialize)] ou println! e veja o código real que ele gera. Insubstituível pra debugar macro procedural.
EspaçorEexplica o erro sob o cursor (o rustc --explain E0502, dentro do editor)
Espaçorhver o HIR (representação de alto nível)
Espaçormver o MIR — útil quando você está brigando com o borrow checker e quer ver onde os empréstimos terminam
Espaçoroabre a página do docs.rs do item sob o cursor no navegador
Espaçorggrafo de dependências entre crates

Navegar no projeto

Espaçorpvai pro módulo pai (de foo/bar.rs pro mod bar; em foo/mod.rs)
Espaçorcabre o Cargo.toml do crate atual
Espaçoracode actions agrupadas do rust-analyzer (mais completo que o Espaçoca genérico)
EspaçorsSSR — busca e substituição estrutural. Ex.: foo($a, $b) ==>> bar($b, $a) troca a ordem dos argumentos em todas as chamadas, entendendo sintaxe.
Espaçorjjoin lines com consciência de sintaxe (junta e conserta vírgulas)

Cargo.toml

Ao abrir um Cargo.toml, o crates.nvim anexa sozinho e mostra a versão mais recente ao lado de cada dependência:

Espaçorcvtodas as versões publicadas desta crate
Espaçorcfas features disponíveis, com quais estão ativas
Espaçorcuatualiza todas as deps pra versão mais nova
Espaçorcdabre a documentação da crate
Espaçorcrabre o repositório
Digitando um nome de crate, o autocomplete busca no crates.io ao vivo.

Como a config trata o Rust

  • Clippy em vez de check — ao salvar roda cargo clippy, não cargo check. Custo quase idêntico, mas você pega idiomatismo além de erro de tipo.
  • Formata ao salvar com rustfmt. Pra desligar num arquivo específico: :FormatToggle!. Globalmente: :FormatToggle.
  • Coluna 100 marcada — o padrão do rustfmt.
  • Autocomplete preenche argumentos — aceite uma função e ela vem com os parâmetros como placeholders; Ctrl+l pula entre eles.
  • Completion postfix — digite valor.ok e aceite: vira Ok(valor). Também .some, .match, .if, .ref.
  • A pasta target/ é ignorada pelo indexador e pela busca.

Trilha · 09

IA

Duas camadas que não se sobrepõem — e essa separação é intencional.

Por que só duas

Copilot, Supermaven, Codeium e os plugins de chat disputam o mesmo texto fantasma e a mesma tecla Tab. Instalar três é garantir sugestões piscando e atalhos que fazem coisas diferentes dependendo de quem respondeu primeiro. A config usa um plugin inline e um gerenciador de agentes — e esse gerenciador fala com todos os CLIs que você já tem.

Camada 1 — Supermaven (inline)

Completa enquanto você digita, em texto cinza à frente do cursor. Sub-100 ms, sem chamar nenhum agente.

Tabaceita a sugestão inteira
Ctrl+→aceita só a próxima palavra (quando ele acertou o começo e errou o resto)
Ctrl+]dispensa a sugestão
EspaçouSliga/desliga o Supermaven

Na primeira vez rode :SupermavenUseFree (plano grátis) ou :SupermavenUsePro. Ele nunca sugere dentro de .env, .pem ou arquivos com "secret" no nome.

Camada 2 — Sidekick (agentes)

Abre um painel à direita com o CLI de verdade rodando — o mesmo claude que você usa no terminal, com suas sessões e sua assinatura. A diferença é que o Neovim injeta contexto automaticamente e recarrega os buffers quando o agente edita arquivos no disco.

O fluxo que economiza mais tempo

Erro de borrow checker que você não entende: Espaçoap → diagnostics. O prompt já vai com o texto exato do erro, o arquivo e a linha. Você não copia nada, não alterna de janela, não explica o contexto.

Os três conceitos

Buffer = um arquivo carregado em memória. Janela = uma viewport que mostra um buffer. Aba = um layout de janelas.
Fechar uma janela não fecha o buffer. Você pode ter 40 buffers abertos e 2 janelas — e isso é o uso normal, não um problema.

Trilha · 13

Macros, registradores e marks

A parte que quase ninguém aprende — e que resolve tarefas repetitivas em segundos.

Registradores

O Vim tem 26 áreas de transferência nomeadas, a a z. Prefixe qualquer verbo com " e a letra:

"ayycopia a linha pro registrador a
"apcola o registrador a
"Ayymaiúscula acrescenta ao registrador em vez de substituir — colete 5 linhas espalhadas e cole todas juntas
"0pcola o último yank, mesmo que você tenha deletado coisas depois. Salva-vidas.
"+ycopia pro clipboard do sistema (na sua config o y normal já faz isso)
Espaços"ver o conteúdo de todos os registradores

Macros

Gravar uma sequência de comandos e repetir N vezes:

  1. qa — começa a gravar no registrador a (aparece "recording" na statusline)
  2. Faça a edição uma vez, terminando com o cursor posicionado pra próxima repetição (normalmente j0)
  3. q — para de gravar
  4. @a — executa uma vez. @@ repete a última macro.
  5. 50@a — executa 50 vezes
A macro em todas as linhas de uma vez

Selecione as linhas em visual (V) e rode :normal @a. A macro é aplicada em cada linha selecionada. Muito mais previsível que contar quantas vezes repetir.

Macro gravada errado? Ela é só texto num registrador: "ap cola a macro numa linha, você edita como texto normal, e "ayy grava de volta.

Marks

mamarca a posição como a (minúsculas = dentro do arquivo)
'avolta pra linha da marca a
mAmaiúscula = mark global, funciona entre arquivos
'.vai pra última posição editada
''alterna com a posição anterior
Espaçosmlista todas as marks

Uso real: está implementando um trait em um arquivo e consultando a definição em outro? mA num, mB no outro, e alterne com 'A / 'B.

Quickfix

Uma lista de posições no código (arquivo + linha) que você percorre uma a uma. É o mecanismo por trás de "corrigir 30 ocorrências em 12 arquivos".

Ctrl+q (no picker)joga todos os resultados da busca na quickfix
]q / [qpróximo / anterior item
:copen / :ccloseabre / fecha a lista
EspaçoxQa quickfix no Trouble, com preview
:cdo {cmd}roda um comando em cada item da lista

O fluxo completo

  1. Espaçosg e busque unwrap()
  2. Ctrl+q — todas as ocorrências vão pra quickfix
  3. :cdo s/unwrap()/expect("motivo")/g | update
  4. Pronto. O | update salva cada arquivo alterado.

Ou, se quiser olhar um por um: ]q pra navegar, editar, ]q de novo.

Receitas do dia a dia

Tarefas reais, resolvidas de ponta a ponta.

Começar a trabalhar num projeto Rust

  2. Vá até [dependencies], o pra abrir uma linha
  3. Digite o nome — o autocomplete busca no crates.io ao vivo

  2. EspaçorE — a explicação oficial do rustc pra esse código de erro

Loop de TDD
  1. Escreva o #[test]
  2. Espaçorr e escolha o teste (só nesta primeira vez)
  3. Implemente
  4. EspaçorR — roda o mesmo teste sem perguntar
  5. Repita o 3 e o 4. Nunca saia do editor.

Renomear um conceito no projeto inteiro

Se for um símbolo Rust (struct, fn, variável): cursor nele → Espaçocr → digite o nome novo → Enter. O LSP renomeia em todos os arquivos, respeitando escopo, sem tocar em strings.

Se for texto (uma chave de config, uma mensagem): EspaçosR abre o grug-far com preview de todas as ocorrências antes de aplicar.

Revisar o próprio código antes do commit
  1. Espaçogs — os arquivos que você mexeu
  2. Em cada um, ]h percorre os hunks e Espaçoghp mostra o antes
  3. Espaçoap → changes pra uma revisão da IA sobre o diff
  4. Espaçogg pro lazygit, e faça o commit
Entender um código alheio
  1. Espaçocs — outline do arquivo, pra ver a forma geral
  2. Inlay hints ligados mostram todos os tipos inferidos — metade do entendimento vem daí
  3. gd pra descer nas definições, Ctrl+o pra voltar
  4. EspaçogL — o histórico do arquivo diz por que aquilo existe
  5. Trecho denso: vif pra selecionar, Espaçoap → explain
Uma macro procedural não está gerando o que você espera

Cursor no #[derive(...)] ou na invocação da macro → Espaçore. Abre um buffer com o código realmente gerado. É a forma mais direta de descobrir por que aquele impl que você esperava não existe.

Mesma edição em 30 linhas

Se for idêntica e em coluna (adicionar pub, um prefixo): Ctrl+v, desça, I, digite, Esc.

Se envolver lógica: grave uma macro. qa → faça numa linha → q → selecione as outras com V → :normal @a.

Sintomas comuns

Ícones aparecem como quadrados ou "tofu"

A fonte do terminal não é uma Nerd Font. Configure Hack Nerd Font Mono nas preferências do seu emulador de terminal — não é config do Neovim.

O autocomplete de Rust não aparece

  1. :LspInfo — o rust-analyzer está anexado?
  2. Se não: você abriu o nvim de dentro de um diretório sem Cargo.toml na raiz? O rustaceanvim procura o Cargo.toml subindo a árvore.
  3. Ele ainda está indexando? Olhe o canto inferior direito.
  4. :LspRestart força o reinício.

"rust-analyzer not found"

Com rustup: rustup component add rust-analyzer. Confirme com rust-analyzer --version.

Ir pra definição na std não funciona

Falta o código-fonte da std: rustup component add rust-src, depois :LspRestart.

O formatador não roda ao salvar

:ConformInfo mostra o que ele encontrou. Se o autoformat estiver desligado, :FormatToggle religa (e :FormatToggle! alterna só este buffer).

Highlight sumiu ou está errado num arquivo

Parser faltando. :checkhealth nvim-treesitter lista o que existe; :TSInstall {linguagem} instala o que falta.

Um plugin quebrou depois de atualizar

:Lazy → r faz rollback pro último estado conhecido bom. O lazy-lock.json guarda os commits exatos — versione ele junto com a config.

O Sidekick não acha um CLI

:checkhealth sidekick lista o que ele encontrou. Ele procura no $PATH — se o binário está em ~/.local/bin, confirme que esse diretório está no PATH do shell que lançou o Neovim.

Algo está muito errado e você quer recomeçar

# apaga só o estado, preservando a config
rm -rf ~/.local/share/nvim ~/.local/state/nvim ~/.cache/nvim
nvim  # reinstala tudo do zero

Seus backups da config anterior estão em ~/.local/share/nvim.bak.*.

Estender a config

Adicionar um plugin

Crie um arquivo em ~/.config/nvim/lua/plugins/ (ou edite um existente). Qualquer .lua nessa pasta que devolva uma tabela é carregado automaticamente.

-- lua/plugins/meu.lua
return {
  {
    "autor/plugin.nvim",
    event = "VeryLazy",        -- quando carregar
    opts = { ... },            -- vira require("plugin").setup(opts)
    keys = {                   -- carrega só quando a tecla é usada
      { "<leader>zz", "<cmd>PluginDoStuff<cr>", desc = "Faz a coisa" },
    },
  },
}

Salve e rode :Lazy sync.

Sempre preencha o desc

É ele que aparece no which-key e na busca de atalhos. Um atalho sem descrição é um atalho que você vai esquecer.

Adicionar um LSP de outra linguagem

  1. :Mason, busque o servidor, i instala
  2. Em lua/plugins/lsp.lua, adicione o nome em ensure_installed
  3. Se precisar de configuração, adicione um bloco vim.lsp.config("nome", { settings = {...} })

Mudar um atalho

Atalhos globais moram em lua/config/keymaps.lua. Atalhos de plugin ficam no bloco keys do próprio plugin — mude lá, não no keymaps.lua, senão o lazy vai carregar o plugin no atalho antigo.

Mudar o tema

Em lua/plugins/ui.lua, o campo style aceita night, storm, moon ou day. Pra trocar de família inteira, substitua o plugin tokyonight.nvim e ajuste o theme da lualine.

Sobreviver a uma formatação

Existe um repositório pronto em ~/nvim-rust, com a config, o manual e um instalador que reconstrói tudo numa máquina zerada:

~/nvim-rust/
├─ install.sh       ← deps do sistema, rustup, fonte, plugins, parsers, Mason
├─ nvim/            ← a config (copiada para ~/.config/nvim)
├─ docs/manual.html ← este manual
├─ README.md
└─ LICENSE          ← MIT

Numa máquina nova:

git clone <seu-repo> nvim-rust
cd nvim-rust && ./install.sh
./install.shinstala tudo
--dry-runmostra o que faria, sem tocar em nada
--deps-onlysó as dependências do sistema
--no-depssó a config

Configs existentes viram *.bak.<timestamp> — o script nunca apaga nada. Detecta pacman, apt, dnf, zypper e brew.

Mantenha o repo em dia

A config em ~/.config/nvim e a cópia em ~/nvim-rust/nvim/ são arquivos separados. Depois de mexer na config, sincronize antes de commitar:

rsync -a --delete ~/.config/nvim/ ~/nvim-rust/nvim/
cd ~/nvim-rust && git add -A && git commit -m "ajuste X"

O lazy-lock.json vai junto: ele fixa o commit exato de cada plugin, e é o que faz a reinstalação reproduzir a mesma config, não a versão mais nova de cada plugin.
